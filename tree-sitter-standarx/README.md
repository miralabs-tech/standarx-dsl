# tree-sitter-standarx

[Tree-sitter](https://tree-sitter.github.io/) grammar for the
**standarx DSL** (`.sxb`, `.sxd`). Companion to the canonical Rust
parser in [`crates/standarx-dsl`](../crates/standarx-dsl).

What this enables that the Rust parser alone cannot:

- **native syntax highlighting** in neovim (nvim-treesitter), Helix,
  Zed, Sublime, Atom (and anything else that consumes tree-sitter
  grammars),
- **GitHub Linguist** recognition (`.sxb` / `.sxd` highlighted in
  diff views, pull requests, repository pages),
- **AST-aware editing**: tree-sitter text-objects, folding,
  injections, incremental re-parsing on large files.

The Rust parser stays authoritative for semantics. This grammar
mirrors its surface syntax — when one changes, the other must too.

## Files

| Path | Purpose |
|---|---|
| [`grammar.js`](grammar.js) | Tree-sitter grammar definition. |
| `src/parser.c`, `src/grammar.json` | Auto-generated by `tree-sitter generate`. Committed. |
| [`queries/highlights.scm`](queries/highlights.scm) | Highlight capture rules. |
| [`queries/injections.scm`](queries/injections.scm) | Language-injection placeholder. |
| [`test/corpus/`](test/corpus/) | Corpus tests pinning the parse tree shape. |

## Setup

```bash
cd tree-sitter-standarx
bun install            # installs tree-sitter-cli
bunx tree-sitter generate   # writes src/parser.c
bunx tree-sitter test       # runs corpus tests
```

## Wiring into editors

### nvim-treesitter

In `~/.config/nvim/lua/...`:

```lua
require('nvim-treesitter.parsers').get_parser_configs().standarx = {
  install_info = {
    url = 'https://github.com/miralabs-tech/standarx-dsl',
    files = { 'tree-sitter-standarx/src/parser.c' },
    branch = 'main',
  },
  filetype = 'standarx',
}

vim.filetype.add({
  extension = { sxb = 'standarx', sxd = 'standarx' },
})
```

Then `:TSInstall standarx`.

### Helix

In `~/.config/helix/languages.toml`:

```toml
[[language]]
name = "standarx"
scope = "source.standarx"
file-types = ["sxb", "sxd"]
roots = []
comment-token = "#"

[[grammar]]
name = "standarx"
source = { git = "https://github.com/miralabs-tech/standarx-dsl", subpath = "tree-sitter-standarx" }
```

Then `hx --grammar fetch && hx --grammar build`.

### Zed

In `~/.config/zed/settings.json`:

```jsonc
{
  "languages": {
    "Standarx": {}
  }
}
```

And install a community Zed extension that wraps this grammar
(none yet — to be published).

## Status

`0.1.0` — initial cut. Matches the Rust parser's surface syntax
for v1.0 of `standarx-dsl`. The grammar is intentionally pure-JS
(no external scanner) to keep the toolchain minimal; edge cases
involving triple-backtick fences inside multi-line templates may
need an external C scanner in a future minor.

## Keeping the grammar in sync with the Rust parser

When the Rust parser grows a new token kind, AST variant, or
disambiguation rule, this grammar must change too. The test corpus
under [`test/corpus/`](test/corpus/) acts as the regression net —
every parse-tree shape the Rust parser accepts should round-trip
through `tree-sitter test`.
